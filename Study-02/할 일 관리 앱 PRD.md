# 할 일 관리 앱 PRD

버전 1.0 · 2026-10-12 · 개인용 웹 앱 (순수 JavaScript)

## 1. 개요

### 배경

하루에 10\~20개 정도의 할 일을 관리하는 개인 사용자를 위한 가벼운 할 일 앱이다. 별도 설치나 로그인 없이 브라우저에서 바로 열어 쓰고, 닫았다 다시 열어도 데이터가 유지되어야 한다.

### 목적

- 할 일을 빠르게 적고, 끝낸 것을 체크하며, 오늘 얼마나 해냈는지 한눈에 확인한다.
- 업무, 개인, 공부 세 가지 카테고리로 일을 구분해서 본다.
- 프레임워크, 빌드 도구, 서버 없이 HTML, CSS, JavaScript만으로 구현해 유지보수가 쉽다.

## 2. 목표와 비목표

### 목표

1. 할 일 추가부터 완료 체크까지 3초 이내에 끝나는 빠른 입력 경험
2. 새로고침, 브라우저 재시작 후에도 데이터 유지
3. 전체 및 카테고리별 진행률을 항상 화면에 표시
4. 외부 라이브러리 없이 동작 (의존성 0개)

### 비목표 (이번 버전에서 하지 않는 것)

- 회원가입, 로그인, 다중 사용자
- 서버, 데이터베이스, 기기 간 동기화
- 알림, 반복 일정, 마감일 관리
- 협업, 공유 기능

## 3. 사용자와 시나리오

### 사용자

본인 한 명. 데스크톱과 모바일 브라우저 모두에서 쓸 수 있으면 좋다.

### 주요 시나리오

| # | 시나리오 | 기대 결과 |
| --- | --- | --- |
| 1 | 아침에 오늘 할 일 10\~20개를 연속으로 입력한다 | Enter만 눌러 연속 추가, 카테고리는 직전 선택값 유지 |
| 2 | 일을 끝낼 때마다 체크한다 | 체크 즉시 취소선 표시, 진행률 바 갱신 |
| 3 | 업무 일만 모아서 본다 | 카테고리 필터로 해당 항목만 표시 |
| 4 | 오타나 내용을 고친다 | 항목을 눌러 인라인 수정 |
| 5 | 저녁에 진행률을 확인한다 | 전체 및 카테고리별 완료 비율 확인 |
| 6 | 브라우저를 닫았다 다음 날 연다 | 어제 데이터 그대로 복원 |

## 4. 기능 요구사항

우선순위: P0는 출시 필수, P1은 있으면 좋은 기능이다.

### 4.1 할 일 추가 (P0)

- 상단 입력창에 텍스트를 입력하고 Enter 또는 추가 버튼으로 등록한다.
- 입력과 함께 카테고리(업무/개인/공부)를 선택한다. 기본값은 직전에 사용한 카테고리다.
- 빈 문자열이나 공백만 있는 입력은 등록하지 않는다.
- 제목 최대 길이는 100자로 한다.
- 등록 후 입력창을 비우고 포커스를 유지해 연속 입력이 가능하다.

### 4.2 할 일 수정 (P0)

- 항목의 수정 버튼을 누르거나 제목을 더블클릭하면 입력창으로 전환된다.
- Enter로 저장하고 Esc로 취소한다.
- 카테고리도 수정할 수 있다.
- 빈 값으로는 저장되지 않고 기존 값이 유지된다.

### 4.3 할 일 삭제 (P0)

- 각 항목의 삭제 버튼으로 삭제한다.
- 실수 방지를 위해 삭제 직후 "실행 취소" 안내를 5초간 표시한다. (확인 팝업보다 흐름이 덜 끊긴다.)

### 4.4 완료 체크 (P0)

- 체크박스를 누르면 완료 상태가 토글된다.
- 완료 항목은 취소선과 흐린 색으로 표시한다.
- 완료 시각(completedAt)을 기록한다.

### 4.5 카테고리 분류 (P0)

- 카테고리는 업무, 개인, 공부 세 가지로 고정한다.
- 각 카테고리는 고유한 색상 배지로 구분한다.
- 필터 탭: 전체 / 업무 / 개인 / 공부. 선택한 필터는 새로고침 후에도 유지한다.

### 4.6 진행률 보기 (P0)

- 화면 상단에 전체 진행률을 "완료 수 / 전체 수 (퍼센트)"와 진행률 바로 표시한다.
- 카테고리별 진행률(예: 업무 3/7, 개인 2/4, 공부 1/3)을 함께 보여준다.
- 항목이 0개일 때는 0%로 표시하고 0으로 나누는 오류가 없어야 한다.
- 체크, 추가, 삭제 시 즉시 갱신된다.

### 4.7 데이터 영구 저장 (P0)

- 브라우저 localStorage에 JSON으로 저장한다.
- 데이터가 바뀔 때마다 즉시 저장하고, 앱 시작 시 불러온다.
- 저장된 데이터가 없거나 손상되었을 때는 빈 목록으로 시작하고 오류로 멈추지 않는다.

### 4.8 보조 기능 (P1)

| 기능 | 설명 |
| --- | --- |
| 완료 항목 일괄 삭제 | "완료 항목 지우기" 버튼 |
| 정렬 | 미완료 항목을 위, 완료 항목을 아래로 표시 |
| 내보내기/가져오기 | JSON 파일로 백업, 복원 |
| 다크 모드 | 시스템 설정(prefers-color-scheme)을 따름 |
| 드래그로 순서 변경 | HTML5 Drag and Drop 사용 |

## 5. 화면 구성 (UX)

단일 페이지, 위에서 아래로 세 영역으로 구성한다.

1. 헤더와 진행률: 앱 제목, 오늘 날짜, 전체 진행률 바, 카테고리별 진행률
2. 입력 영역: 텍스트 입력창, 카테고리 선택, 추가 버튼
3. 목록 영역: 필터 탭(전체/업무/개인/공부)과 할 일 목록

### 화면 상태

- 빈 상태: "아직 할 일이 없어요. 첫 할 일을 추가해 보세요." 안내 문구
- 모두 완료: 진행률 100%일 때 "오늘 할 일을 모두 끝냈어요" 메시지 표시
- 필터 결과 없음: "이 카테고리에는 할 일이 없어요"

### 디자인 원칙

- 한 화면에서 20개 항목이 스크롤 없이 또는 최소한의 스크롤로 보이도록 항목 높이를 컴팩트하게 한다.
- 모바일(폭 360px 이상)에서도 깨지지 않는 반응형 레이아웃
- 키보드만으로 추가, 체크, 수정이 가능해야 한다. (접근성)

## 6. 데이터 모델

### 할 일 (Todo)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID (Date.now() 기반 또는 crypto.randomUUID()) |
| title | string | 할 일 내용, 1\~100자 |
| category | string | "work" \| "personal" \| "study" |
| completed | boolean | 완료 여부 |
| createdAt | number | 생성 시각 (timestamp) |
| completedAt | number \| null | 완료 시각, 미완료는 null |

### 저장 구조 (localStorage)

- 키 `todoApp.todos`: Todo 배열의 JSON 문자열
- 키 `todoApp.settings`: 선택한 필터, 마지막 사용 카테고리
- 데이터 구조 변경에 대비해 `todoApp.version` 키에 스키마 버전을 저장한다.

```json
[
  {
    "id": "1760227200000",
    "title": "주간 보고서 작성",
    "category": "work",
    "completed": false,
    "createdAt": 1760227200000,
    "completedAt": null
  }
]
```

## 7. 기술 요구사항

### 스택

- HTML5, CSS3, 순수 JavaScript (ES6+)
- 프레임워크, 번들러, 외부 라이브러리 사용하지 않음
- 브라우저에서 index.html을 열면 바로 실행 (서버 불필요)

### 파일 구조

```
todo-app/
├── index.html
├── style.css
└── app.js
```

작은 앱이므로 세 파일로 충분하다. 코드가 길어지면 app.js 안에서 저장소(storage), 상태(state), 화면 그리기(render) 영역으로 나눈다.

### 구현 방침

- 상태 관리: 하나의 `todos` 배열을 단일 진실 원천으로 두고, 변경 시마다 `save()`와 `render()`를 호출한다.
- 이벤트 처리: 목록 컨테이너 하나에 이벤트 위임으로 체크, 수정, 삭제를 처리한다.
- 보안: 사용자 입력은 `innerHTML` 대신 `textContent`로 삽입해 의도치 않은 HTML 실행을 막는다.
- 저장 오류 처리: localStorage 읽기/쓰기는 try/catch로 감싸고, 실패 시 화면에 안내를 표시한다. (시크릿 모드나 용량 초과 대비)

### 지원 브라우저

최신 Chrome, Edge, Safari, Firefox

### 알려진 제약

- localStorage는 브라우저, 기기, 도메인마다 따로 저장된다. 다른 브라우저나 기기에서는 데이터가 보이지 않는다.
- 브라우저 설정에서 사이트 데이터를 삭제하면 할 일도 함께 지워진다. 그래서 백업(P1 내보내기)이 의미가 있다.
- `file://`로 열었을 때 브라우저에 따라 저장 공간이 분리될 수 있으므로, 같은 경로로 계속 여는 것을 권장한다.

## 9. 수용 기준 (완료 정의)

- [ ] 할 일을 추가하면 목록에 즉시 나타나고, 빈 입력은 추가되지 않는다.
- [ ] 항목을 수정하면 저장되고, Esc로 취소할 수 있다.
- [ ] 삭제하면 목록에서 사라지고, 5초 안에 실행 취소할 수 있다.
- [ ] 체크하면 취소선이 표시되고 진행률이 즉시 갱신된다.
- [ ] 업무/개인/공부 카테고리로 분류되고 필터로 걸러볼 수 있다.
- [ ] 전체 및 카테고리별 진행률이 정확하게 표시된다. (0개일 때도 오류 없음)
- [ ] 새로고침 후에도 할 일, 완료 상태, 선택한 필터가 유지된다.
- [ ] 손상된 저장 데이터가 있어도 앱이 멈추지 않는다.
- [ ] 모바일 폭(360px)에서 레이아웃이 깨지지 않는다.

## 12. 확인이 필요한 질문

1. 할 일을 "오늘" 단위로 관리하는가, 날짜 구분 없이 하나의 목록으로 계속 쌓는가? 이 문서는 후자(단일 목록)를 가정했다.
2. 완료한 항목은 다음 날 자동으로 정리되길 원하는가, 직접 지울 때까지 남겨둘 것인가?
3. 카테고리는 세 가지로 고정해도 충분한가, 나중에 직접 추가하고 싶은가?
4. 백업(내보내기) 기능은 첫 버전에 꼭 필요한가?
